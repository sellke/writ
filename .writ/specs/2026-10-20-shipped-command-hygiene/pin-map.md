One row per `require_literal`, `forbid_literal`, or `forbid_literal_ci` instance in `scripts/eval.sh` whose target is a `commands/` file; a loop over several files is one row per file. `Line` is the eval.sh line at the inventory commit. The recipe parsed 572 pin call lines, equal to `grep -c` of pin call lines. Its 22 unresolved targets are all spec files read through `resolve_spec_path` (`check_autonomy_governance`, `check_recommended_spec_implementation`, `check_exit_criteria`), so none adds a row. Re-inventoried after the change: the recipe parsed 518 pin call lines, equal to `grep -c` 518, with the same 22 unresolved spec-file targets. Every keep literal is still pinned on its target, no convert or remove literal remains on its target, and the count fell by 63 (convert 29 + remove 34).

How the dispositions were decided:

- The seven safety categories (`prime-directive`, `recommend-boundary`, `gate-class`, `loop-bound`, `script-invocation`, `verdict-provenance`, `parsed-format`) take only keep or convert. A row that fits two categories takes the stricter one.
- A convert row is now a row in `scripts/eval-command-structure.py`, run by `check_command_structure`. Its reason names the structural row; row 74 became two rows. An invocation row names the subcommand the command must call and keeps every flag and argument the literal bound, so it is never weaker than the pin it replaces.
- A remove row is wording, retired text, or a structure pin with no safety role. Four structure rows (130, 132, 135, 136) are removed because an `eval-*.py` scenario run by the same check asserts the same text on the same file.
- Rows 47-49 and 182 differ from the technical spec's guidance (remove candidates there). Rows 47-49 are the release test gate's decision table, and row 182 is an exit criterion; both stay.
