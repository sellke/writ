## S1 Snapshot

The caller writes the snapshot. `pr-ready.py` only reads it.

```json
{
  "schema": "pr-ready-snapshot/1",
  "view": { "...": "stdout of the gh pr view command" },
  "threads": { "...": "stdout of the gh api graphql command" }
}
```

### Commands

`pr-ready.py --help` prints this block verbatim (module docstring, `RawDescriptionHelpFormatter`). `$N` is the PR number and `$SNAP` the snapshot path. Run it from the repository root.

```bash
VIEW=$(gh pr view "$N" --json number,url,state,isDraft,mergeable,mergeStateStatus,reviewDecision,headRefOid,baseRefName,statusCheckRollup) &&
THREADS=$(gh api graphql -F owner='{owner}' -F name='{repo}' -F number="$N" -f query='query($owner:String!,$name:String!,$number:Int!){repository(owner:$owner,name:$name){pullRequest(number:$number){number headRefOid reviewThreads(first:100){totalCount pageInfo{hasNextPage} nodes{id isResolved isOutdated path line comments(first:1){nodes{author{login}}}}}}}}') &&
printf '{"schema":"pr-ready-snapshot/1","view":%s,"threads":%s}\n' "$VIEW" "$THREADS" > "$SNAP.tmp" && mv "$SNAP.tmp" "$SNAP"
```

- `gh api -F` fills `{owner}` and `{repo}` from the current repository (`gh api --help`, gh 2.96.0).
- A failed `gh` call leaves `$VIEW` or `$THREADS` empty. The `&&` chain then stops before `printf`. A partial file that still gets through fails JSON parsing: exit 2.
- The query requests no comment body.
- Suggested path, used by the second spec: `.writ/state/pr-ready/pr-<n>.json`.
- The docstring holds `%s` but no `%(prog)`, so argparse prints it unchanged.

### Fields read

| Source | Field | Type | Accepted values |
|---|---|---|---|
| `view` | `number` | int ≥ 1 | |
| `view` | `state` | str | `OPEN`, `CLOSED`, `MERGED` |
| `view` | `isDraft` | bool | |
| `view` | `mergeable` | str | `MERGEABLE`, `CONFLICTING`, `UNKNOWN` |
| `view` | `mergeStateStatus` | str | `CLEAN`, `HAS_HOOKS`, `UNSTABLE`, `BLOCKED`, `BEHIND`, `DIRTY`, `DRAFT`, `UNKNOWN` |
| `view` | `reviewDecision` | str or null | `APPROVED`, `CHANGES_REQUESTED`, `REVIEW_REQUIRED`, `""`, null |
| `view` | `headRefOid` | str | 40 lowercase hex |
| `view` | `statusCheckRollup` | list or null | entries below; null reads as `[]` |
| `threads` | `data.repository.pullRequest.number` | int | equals `view.number` |
| `threads` | `data.repository.pullRequest.headRefOid` | str | 40 lowercase hex |
| `threads` | `...reviewThreads.totalCount` | int | |
| `threads` | `...reviewThreads.pageInfo.hasNextPage` | bool | |
| `threads` | `...reviewThreads.nodes[]` | list | `id` str, `isResolved` bool, `isOutdated` bool, `path` str or null, `line` int or null, `comments.nodes[0].author.login` str or null (any level may be null) |

`url` and `baseRefName` are fetched for the caller and not judged. Unknown extra keys are ignored.

`statusCheckRollup` entries:

| `__typename` | Name field | Passing | Pending | Failing |
|---|---|---|---|---|
| `CheckRun` | `name` | `status` `COMPLETED` and `conclusion` in `SUCCESS`, `NEUTRAL`, `SKIPPED` | `status` in `QUEUED`, `IN_PROGRESS`, `WAITING`, `PENDING`, `REQUESTED` | `status` `COMPLETED` and `conclusion` in `FAILURE`, `TIMED_OUT`, `CANCELLED`, `ACTION_REQUIRED`, `STARTUP_FAILURE`, `STALE` |
| `StatusContext` | `context` | `state` `SUCCESS` | `state` in `PENDING`, `EXPECTED` | `state` in `FAILURE`, `ERROR` |

Any other `__typename`, `status`, `conclusion`, or `state` value is a snapshot that cannot be judged (exit 2, `pr-ready: snapshot <path>: unrecognized <field> <value>`). A value outside these tables means `gh` or GitHub changed shape. Guessing would hide it.

## S2 `pr-ready.py`

```
python3 scripts/pr-ready.py check --snapshot <file> [--repo .] [--json]
```

`--json` arrives in Story 3. `--repo` names the checkout whose `.writ/state/verify-ledger.json` and git objects the ledger gate reads (Story 3).

### Evaluation

1. Load and validate the snapshot (§ S1). Any defect: exit 2, stdout empty, `pr-ready: snapshot <path>: <cause>` on stderr.
2. Collect blockers per class, in class order (spec.md → Business Rules (Expanded)).
3. Collect unknowns.
4. Story 3: run the ledger gate (§ S3) and add `not_verified` to `merge_gates` when it does not pass.
5. Compute `merge_state_blocked` last, because it depends on everything else.
6. Pick the verdict and exit code (spec.md → § Verdict and exit code).

Code shape: a pure `evaluate(snapshot: dict, ledger: Optional[Callable]) -> Result` (`Result` holds `verdict`, `exit`, `pr`, `head`, `blockers`, `unknowns`, `ledger`) and a thin CLI. Story 2 passes `ledger=None`. Story 3 passes the loaded `ledger_check`.

### Output

```
<verdict>
reason: <class>: <detail>        one per blocker, class order
reason: unknown: <code> [detail] one per unknown
pr-ready: <verdict> (<summary>)
```

| Line | Format |
|---|---|
| conflicts | `conflicts: mergeable <MERGEABLE\|CONFLICTING\|UNKNOWN> (merge state <S>)` |
| thread | `unresolved_threads: <id> <path\|?>:<line\|?> by <login\|?>` plus ` outdated` when `isOutdated` |
| check | `failing_checks: <name> <conclusion or state>` |
| gate | `merge_gates: <token>` plus a detail: `not_open <STATE>`; `not_verified head <short>: <ledger reason>` |
| unknown | `unknown: checks_pending <name>[, <name>...]`, `unknown: mergeable_unknown`, `unknown: threads_truncated <fetched> of <total>`, `unknown: head_moved <view short> <threads short>`, `unknown: merge_state_unexplained UNSTABLE` |

Summaries (`<short>` = first 7 hex of `headRefOid`):

- `pr-ready: pass (PR <n> head <short>, ledger VERIFIED)`. Before Story 3 it is `pr-ready: pass (PR <n> head <short>)`.
- `pr-ready: fail (PR <n> head <short>, blockers: <classes present, comma-separated>; exit <code>)`
- `pr-ready: unverifiable (PR <n> head <short>, unknown: <codes, comma-separated>)`

Every printed snapshot string goes through `printable` (copied from `scripts/repro-order.py`): C0, DEL, C1, U+2028, and U+2029 become escapes. stdout is reconfigured with `errors="backslashreplace"` as in `repro-order.py`.

### `--json` (Story 3)

All of stdout is one JSON object. The verdict lines are not printed. The exit code equals the text run's.

```json
{
  "verdict": "fail",
  "exit": 6,
  "pr": 66,
  "head": "9f1e2a7c0d4b5e6f7a8b9c0d1e2f3a4b5c6d7e8f",
  "blockers": [{"class": "merge_gates", "detail": "not_verified head 9f1e2a7: patch_id_mismatch ..."}],
  "unknowns": [{"code": "checks_pending", "detail": "ci/test"}],
  "ledger": {"verdict": "fail", "reasons": ["patch_id_mismatch ..."]}
}
```

- `head` is the full 40-hex `headRefOid`.
- `blockers[].detail` is the text after `reason: <class>: `, so a `merge_gates` detail starts with its gate token. The second spec reads `detail.startswith("not_verified")`.
- `ledger.verdict` is `pass` or `fail`, and `ledger.reasons` is the list `ledger_check` returned. For an unreadable ledger, it is `fail` and `["ledger_unreadable (<detail>)"]`.
- Strings in the JSON are not escaped by `printable`. `json.dumps` escapes control characters itself (`ensure_ascii=True`).

## S3 Ledger gate (Story 3)

- Load `verify-ledger.py` from `Path(__file__).resolve().parent` with the `_load_sibling` pattern in `scripts/exit-criteria.py`, module name `verify_ledger_for_pr_ready`, deferred to first use. A missing file or a load error: exit 2, `pr-ready: cannot load verify-ledger.py (<cause>)`.
- Call `ledger_check(repo, pr=view.number, head=view.headRefOid)`. `base` is omitted, so the ledger uses the PR's most recent row's `base_ref`.
- `pass`: no gate. `fail`: `merge_gates: not_verified head <short>: <first reason>`.
- The ledger module's `LedgerError` (unreadable or malformed file): `merge_gates: not_verified ledger_unreadable (<detail>)`. The other blockers still print, and the exit code follows class order.

## S4 `verify-ledger.py`

```
python3 scripts/verify-ledger.py record --pr N --head SHA --base REF --evidence EXIT CMD [--evidence EXIT CMD ...] [--repo .]
python3 scripts/verify-ledger.py check  --pr N --head SHA [--base REF] [--repo .]
```

`--evidence` is `nargs=2`, `action="append"`, and required for `record`: the exit code, then the command string.

### File

`<repo>/.writ/state/verify-ledger.json`:

```json
{
  "schema": "verify-ledger/1",
  "rows": [
    {
      "pr": 66,
      "head": "3ddc8c8f0e1d2c3b4a5968778695a4b3c2d1e0f9",
      "patch_id": "99ab09152654023043900f09c258ba8581370cce",
      "base_ref": "origin/main",
      "merge_base": "541252b0a1b2c3d4e5f60718293a4b5c6d7e8f90",
      "recorded_at": "2026-11-06T18:04:00Z",
      "evidence": [
        {"command": "uv run --isolated --python 3.9 --with pytest pytest", "exit": 0},
        {"command": "bash scripts/eval.sh", "exit": 0}
      ]
    }
  ]
}
```

- `patch_id` and `merge_base` may be null. `head` and `merge_base` are full object ids (40 hex; 64 in a SHA-256 repository).
- A missing file reads as `{"schema": "verify-ledger/1", "rows": []}`.
- An unreadable file, invalid JSON, another `schema`, or a row with a missing or mistyped field raises `LedgerError`. `check` maps it to exit 2. `pr-ready.py` maps it to `not_verified ledger_unreadable`. `record` exits 2 and does not overwrite the file.
- Writes: `json.dumps(..., indent=2, sort_keys=True) + "\n"` into `tempfile.mkstemp(dir=<state dir>, suffix=".tmp")`, then `os.replace`. Remove the temp file on any error. Create `.writ/state/` with `mkdir(parents=True, exist_ok=True)`.

### Patch-id

```
merge_base = git merge-base <base_sha> <head_sha>
git diff --no-color --no-ext-diff --no-textconv --binary --full-index --no-renames \
         --src-prefix=a/ --dst-prefix=b/ --diff-algorithm=myers -U3 --no-relative \
         <merge_base> <head_sha>
  | git patch-id --verbatim          → first whitespace-separated field
```

- Run every git call as `git -C <repo> ...` with `capture_output=True`, `check=False`. The diff stdout is bytes and goes to `patch-id` as `input=` bytes.
- **Feature detection:** run `git patch-id --verbatim` once with empty input. Exit 0 means it is supported. Anything else means `patch_id_unavailable (verbatim_unsupported)`.
- **Empty diff:** `patch-id` prints nothing, so the result is `patch_id_unavailable (empty_diff)`.
- **No merge base:** `git merge-base` exits 1, so the result is `patch_id_unavailable (no_merge_base)`, and `merge_base` is stored as null.

### `record`

1. Validate arguments. Each evidence exit must parse as an int, each command must be non-empty, and `--pr` must be ≥ 1. `--repo` must be a git work tree. Otherwise exit 2.
2. Resolve `--head` and `--base` to full ids with `rev-parse --verify --quiet <rev>^{commit}`. Reject a leading `-`. An unresolvable rev is exit 2.
3. Collect refusals, printing every one that holds:
   - `evidence_failed <exit> <command>` for each non-zero exit
   - `head_not_checked_out <short head> (HEAD is <short>)`
   - `dirty_tree <n> path(s)` from `git status --porcelain --untracked-files=no`
   On any refusal: `fail`, the reasons, `verify-ledger: fail (record refused for PR <n> head <short>)`, exit 1. Nothing is written.
4. Load the ledger. Compute `merge_base` and `patch_id`. Build the row with `recorded_at` from `datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")`.
5. Replace the row with the same `(pr, head)`, or append. Write atomically.
6. Print `pass`, then `reason: recorded PR <n> head <short> patch-id <short|null>`, then `reason: replaced` when a row was replaced, then `reason: patch_id_unavailable (<why>)` when the id is null, then `verify-ledger: pass (recorded PR <n> head <short>, <k> command(s))`. Exit 0.

### `check` and `ledger_check`

`ledger_check(repo: Path, pr: int, head: str, base: Optional[str] = None) -> Tuple[str, List[str]]` is public. It raises `LedgerError` and never prints. The CLI wraps it.

1. Load the ledger and take the rows with `row.pr == pr`. None: `("fail", ["no_rows PR <n>"])`.
2. When `head` is full hex, lowercase it. A row with that head: `("pass", ["verified_exact <short> (recorded <recorded_at>)"])`.
3. Otherwise resolve `head` with git (`head_unavailable <head>` on failure). Repeat step 2 with the resolved id.
4. Pick the base: `base`, or the `base_ref` of the PR's row with the latest `recorded_at`. If it does not resolve: `base_unavailable <ref>`. Compute the id. If none: `patch_id_unavailable (<why>)`.
5. A row of this PR with an equal non-null `patch_id`: `("pass", ["verified_patch_id <short head> matches <short row head>"])`. Else `("fail", ["patch_id_mismatch <short head> patch-id <short id> matches no verified row for PR <n>"])`.

Summaries: `verify-ledger: pass (PR <n> head <short> VERIFIED, exact|patch-id)` and `verify-ledger: fail (PR <n> head <short> NOT VERIFIED, <first code>)`.

Exit codes: 0 pass, 1 fail, 2 usage or could not start (unreadable or malformed ledger, `--repo` not a directory, git not found for `record`). Inside `ledger_check`, a missing `git` is `patch_id_unavailable (git_not_found)`, so `check` and `pr-ready.py` fail closed instead of exiting 2.

## Error & Rescue Map

| Operation | What Can Fail | Planned Handling | Test Strategy |
|---|---|---|---|
| Read snapshot | Missing, unreadable, not JSON | Exit 2, stdout empty, `pr-ready: snapshot <path>: <cause>` | Missing path; `not-json.txt` |
| Validate snapshot | Wrong `schema`, `view`/`threads` missing, GraphQL `errors`, missing or mistyped field, PR-number mismatch | Exit 2, cause names the field | `bad-schema.json`, `graphql-errors.json`, `missing-field.json`, `pr-mismatch.json` |
| Validate snapshot | Unrecognized enum value | Exit 2, `unrecognized <field> <value>` | `unknown-conclusion.json` |
| Judge threads | More than 100 threads | `unknown: threads_truncated`; unresolved threads in the page still block | `threads-truncated.json` |
| Judge threads | Hostile text in fields, a `body` key present | Escaped identifiers only; no body printed | `hostile-thread.json` |
| Load ledger module | `verify-ledger.py` missing beside `pr-ready.py` | Exit 2, `cannot load verify-ledger.py` | Copy `pr-ready.py` alone into `tmp_path` |
| Read ledger (pr-ready) | Malformed file | `merge_gates: not_verified ledger_unreadable (...)`; other blockers print | Write `{"schema": "x"}` to the ledger path |
| Read ledger (check) | Malformed file | Exit 2, stdout empty | Same file, `verify-ledger.py check` |
| Record | Evidence exit non-zero, head not checked out, tracked change | `fail`, every refusal reason, exit 1, file byte-identical | Temp repo, one case each, compare bytes before and after |
| Record | Unresolvable `--head` or `--base`, bad `--evidence` exit | Exit 2 | Temp repo |
| Write ledger | Disk error during the write | Temp file removed, target untouched, exit 2 | Monkeypatch `os.replace` to raise |
| Compute patch-id | `git patch-id --verbatim` unsupported | Row `patch_id: null`; `check` on another head: `patch_id_unavailable` | `PATH` shim `git` |
| Compute patch-id | Empty diff, no merge base | `patch_id: null` with the reason | Head equal to base; unrelated histories |
| Compute patch-id | Hostile user diff config | Same id as default config | `GIT_CONFIG_GLOBAL` file with `diff.noprefix`, `diff.algorithm=patience`, `diff.renames=copies`, `color.ui=always` |
| Check | Head not in the clone, base not resolvable | `fail`, `head_unavailable` / `base_unavailable` | SHA of a commit made in another repo; deleted ref |
| Run git | `git` not on `PATH` | `record`: exit 2 (`git not found`). `check`: an exact head still answers; otherwise `fail patch_id_unavailable (git_not_found)` | `PATH` without git |

## Shadow Paths

| Flow | Happy Path | Nil Input | Empty Input | Upstream Error |
|---|---|---|---|---|
| `pr-ready.py check` | Clean snapshot, verified head → `pass`, exit 0 | `--snapshot` names a missing file → exit 2 | No checks, no threads, clean, verified → `pass` | `threads.errors` present → exit 2 |
| `verify-ledger.py record` | Clean head, all exits 0 → row written, `pass` | No `--evidence` → argparse exit 2 | Empty diff → row with `patch_id: null`, `pass` | Old git → row with `patch_id: null`, `pass` |
| `verify-ledger.py check` | Exact head → `pass verified_exact` | No ledger file → `fail no_rows` | Ledger with no row for the PR → `fail no_rows` | Malformed ledger → exit 2 |

## Interaction Edge Cases

| Case | Behavior |
|---|---|
| Force-push back to a verified head | `verified_exact`. |
| A commit added and then reverted, with the net diff unchanged | Same patch-id: `verified_patch_id`. The tree relative to the base is the same. |
| Rebase onto a base that changed a line inside the PR's hunk context | Different id: NOT VERIFIED. Fails closed. |
| Two `record` runs at once | One row may be lost. The later `check` reads NOT VERIFIED and the merge asks. |
| Re-record the same head with new evidence | The row is replaced. |
| PR retargeted to another base branch after a record | The exact head still reads VERIFIED. A new head is computed against the old row's `base_ref`. Accepted (spec.md → Technical Concerns). |
| Checks pending and a thread unresolved | `fail` exit 4, plus `unknown: checks_pending`. |
| `BLOCKED` with review required | Only `review_required`. `merge_state_blocked` does not print. |
| `BLOCKED`, ledger not verified, nothing else | Both `not_verified` and `merge_state_blocked` print. |
| `UNSTABLE` with a failing optional check | `failing_checks`. No unknown. |
| `head_moved` together with a blocker | `fail` by the blocker. The unknown is listed. |
