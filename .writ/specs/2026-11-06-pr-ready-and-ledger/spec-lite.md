# PR Ready and Verification Ledger (Lite)

> Source: .writ/specs/2026-11-06-pr-ready-and-ledger/spec.md
> Purpose: Efficient AI context for implementation

## For Coding Agents

**Deliverable:** `scripts/pr-ready.py` (read-only) judges a saved `gh` snapshot of one PR into typed blockers with one exit code per class. `scripts/verify-ledger.py` records verified PR heads and answers VERIFIED by exact SHA or same-PR verbatim patch-id.

**Implementation Approach:**
- Both scripts use the check shape: verdict on line 1, `reason:` lines, summary last. Stdlib, Python 3.9, standalone. Copy `_git`, `_resolve`, `printable` (`repro-order.py`), `_load_sibling` (`exit-criteria.py`), and the atomic write (`phase-state.py`).
- `pr-ready.py check --snapshot <f> [--repo .] [--json]`. Exit 0 pass/unverifiable, 2 usage or bad snapshot, 3 conflicts, 4 unresolved_threads, 5 failing_checks, 6 merge_gates (first class present), never 1.
- Ledger: `<repo>/.writ/state/verify-ledger.json`, schema `verify-ledger/1`, one writer (`record`), `mkstemp` + `os.replace`.
- Patch-id: `git patch-id --verbatim` over a pinned `git diff` (technical-spec § Patch-id, plus `-c diff.suppressBlankEmpty=false --inter-hunk-context=0 --indent-heuristic --ignore-submodules=none --submodule=short`, run without `GIT_DIFF_OPTS`/`GIT_EXTERNAL_DIFF`; DEV-001), passed as bytes; null when unsupported, empty, or no merge base.
- `pr-ready.py` loads `verify-ledger.py` from its own directory (with `sys.dont_write_bytecode` set, so no `__pycache__` is written) and calls `ledger_check(repo, pr, head)` through `ledger_gate(repo)`, a `(pr, head)` wrapper that maps `LedgerError` to `fail` with `ledger_unreadable (<detail>)`; a module without `ledger_check` or `LedgerError` is a load error, exit 2 (Story 3, DEV-009).

**Files in Scope:**
- `scripts/verify-ledger.py`, `scripts/pr-ready.py`: new
- `scripts/tests/test_verify_ledger.py`, `scripts/tests/test_pr_ready.py`, `scripts/tests/fixtures/pr-ready/*`: new
- `.writ/docs/agent-cli-contract.md`: two rows, two Notes entries, one Check-shape bullet
- `.writ/decision-records/adr-029-agent-cli-contract.md`: 2026-11-06 amendment (rules 1-7 untouched)
- `scripts/tests/test_agent_cli_contract.py`: two smokes, `FAIL_EXITS`, two appended tests (`test_fail_exits_are_documented`, `test_fail_exits_apply_only_to_listed_scripts`), and `test_every_test_names_its_ac_id` widened to accept a later spec's AC IDs beside its name (DEV-007)
- `plugins/writ/scripts/`: regenerated by `python3 scripts/gen-platform-trees.py`
- Never: `commands/ship.md`, `commands/_preamble.md`, `scripts/jev-judge.py`, `recommendation-semantics.md`, `roadmap.md`

**Error Handling:**
- Bad snapshot (missing, not JSON, schema, GraphQL `errors`, field, enum, PR mismatch) → exit 2, stdout empty. A running `CheckRun` may carry conclusion `""` or null (DEV-005); a missing key in the comments chain reads as null and prints `?` (DEV-006); a rejected enum or `schema` value prints cut to 80 characters, as a JSON scalar, or as `<type>` (DEV-008)
- Ledger unreadable → `check` exit 2; inside `pr-ready.py` → `merge_gates: not_verified ledger_unreadable`
- Patch-id not computable → NOT VERIFIED (fail closed); any other git failure → `patch_id_unavailable (git_failed)` (DEV-002); `record` refusal → `fail`, exit 1, nothing written; its tracked-change check uses `--ignore-submodules=untracked` (DEV-004)

## For Review Agents

**Acceptance Criteria:**
1. `record` writes a row only for passing evidence on the clean checked-out head; `check` passes on the exact head `[AC-1.1, AC-1.2]`
2. Each single-property mutation of a verified head reads NOT VERIFIED; an identical-diff rebase reads VERIFIED `[AC-1.3, AC-3.2]`
3. Hostile diff config does not change the id; every uncomputable id fails closed `[AC-1.4]`
4. Each blocker fixture gives its class, gate token, and exit code; all four print in class order `[AC-2.1, AC-2.2]`
5. Bad snapshots exit 2 with stdout empty; `--help` prints the `gh` commands verbatim `[AC-2.3]`
6. No comment body is printed; snapshot strings are escaped `[AC-2.4]`
7. A clean verified snapshot passes; a changed head exits 6 with `not_verified` `[AC-3.1]`
8. `--json` has the seven keys, full 40-hex `head`, and the text run's exit code `[AC-3.4]`
9. Contract rows, Notes, Check-shape exception, ADR-029 amendment, smokes, and plugin copies pass their checks `[AC-1.5, AC-2.5, AC-3.5]`

**Business Rules:**
- `pr-ready.py` makes no network call, writes nothing, never sleeps or loops
- `fail` if any blocker; else `unverifiable` if any unknown; else `pass` (ledger VERIFIED required)
- Every failing check blocks, required or not; `changes_requested` and `review_required` are merge gates
- Every `merge_gates` detail starts with its gate token; `not_verified` never explains GitHub `BLOCKED`
- Patch-ids never match across PRs; same (PR, head) re-record replaces the row

**Experience Design:**
- Entry: `/ship --watch` (second spec) or by hand
- Happy path: record → snapshot → `check` → `pass`, exit 0
- Moment of truth: `pr-ready: pass (PR 66 head 3ddc8c8, ledger VERIFIED)`
- Feedback: one `reason:` line per blocker or unknown
- Error: new head → `merge_gates: not_verified`, exit 6; pending checks → `unverifiable`, exit 0

## For Testing Agents

**Success Criteria:**
1. Every fixture prints the expected line 1, reasons, and exit on Python 3.9 and 3.14
2. The mutation test asserts the exact verdict and reason per mutation
3. `test_agent_cli_contract.py`, `test_agent_cli_contract_doc.py`, `gen-platform-trees.py --check` pass

**Shadow Paths to Verify:**
- **Happy path:** verified head + clean snapshot → `pass`, exit 0
- **Nil input:** missing snapshot → exit 2; no ledger file → `no_rows`
- **Empty input:** no checks, no threads → no blocker; empty diff → `patch_id: null`
- **Upstream error:** GraphQL `errors` → exit 2; old git → exact-head only

**Edge Cases:**
- `BLOCKED` + `REVIEW_REQUIRED` → only `review_required`
- Threads > 100 → `unknown: threads_truncated`; two calls saw two heads → `unknown: head_moved`

**Coverage Requirements:**
- New code: ≥80%. Critical paths and error paths: 100%

**Test Strategy:**
- Temp git repos in a temp dir (`unittest` + `tempfile`, house style; DEV-003); never the Writ checkout's `.writ/state/`. Run pytest alone.
