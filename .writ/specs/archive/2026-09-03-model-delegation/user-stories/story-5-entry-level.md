## User Story

**As a** Writ maintainer implementing ADR-024 (command author)
**I want to** confirm the `entry_level` derivation table with one bounded question, declare `entry_level: high | standard | any` in the existing `---` frontmatter of all 31 `commands/*.md`, verify the one-line entry-notice rule lives exactly once in `system-instructions.md` § Model Tiers (mirrored in `cursor/writ.mdc`) and nowhere in any command, and give the field two consumers — a `lint-skill.sh` value check with a script test and a non-blocking `eval.sh` presence note

## Notes

**Self-assessment can be wrong both ways.** The entry check is the running model judging its own origin against plain guidance (`high`: frontier-class model of its family at a non-minimal thinking level; `standard`: non-smallest model or medium-plus effort; `any`: nothing). Writ maintains no model ranking (Business Rule 9), so a false notice and a missed notice are both possible. The design accepts this because the cost of either error is one advisory line: it never asks, never blocks, and the command continues (spec.md Technical Concerns, State catalog "Origin below `entry_level`"). Do not add a ranking, a threshold table, or a confirmation prompt to "fix" a wrong self-assessment — that is out of scope (a blocking entry gate is excluded) and would reintroduce the judgment ADR-023 forbids inventing evidence for.

**The check text lives in the root contract, not per command.** Technical-spec §5 is placed once in `system-instructions.md` § Model Tiers (paid once per invocation) and mirrored into `cursor/writ.mdc`. Commands carry only the declaration. Repeating the blockquote in 31 files would multiply the byte budget hit and create 31 drift points; `commands/_preamble.md` is at its 95-line hard cap (`eval.sh` ~line 421 enforces) and absorbs nothing. Story 1 owns the text; this story verifies it and repairs only if it is missing, which is why 5.3 comes before 5.4.

**`_preamble.md` is excluded everywhere.** It is not a command: no `entry_level:`, no lint expectation, and the eval note must skip it explicitly or the note fires on every run.

**Derivation, not taste.** The 14/12/5 table is *proposed* in spec.md and the maintainer confirms it in 5.2 via one bounded AskQuestion — this is a known option space, so Plan Mode is not used. Any re-classification must cite Q1 or Q2; `/implement-spec` and `/implement-story` both stay `high` with no finer ordering (ADR-024 A3). If the maintainer re-classifies, update the spec.md table so the Success Criterion `rg "entry_level:" commands/*.md` → 31 still has a table to be checked against.

**Risks.** (1) Frontmatter edits across 31 files — one malformed YAML line (a stray quote, a tab, a misplaced `- ` list marker, or inserting inside the `exit_criteria:` list) breaks `scripts/exit-criteria.py`'s parse and the `require_literal` pins in `eval.sh` `check_exit_criteria` that read command frontmatter. Insert as a bare scalar on its own line between `outcome:` and `exit_criteria:`, then run the eval before committing. (2) `create-spec.md` and `implement-story.md` are already over the non-blocking byte budget; one 20-byte line each is acceptable per ADR-023's triage and adds no finding. (3) `rg -c` counts lines; a command that mentions `entry_level:` in body prose at column 0 would inflate the count — the `^entry_level:` anchor plus manual inspection of the 31 lines in 5.7 catches it. (4) A test that runs `eval.sh` against the real repo cannot fixture a missing field, hence the temp-root harness borrowed from `test_eval_length_caps.sh`.

**Integration.** Story 1 supplies the `entry_level` lint grammar (`^(high|standard|any)$`, technical-spec §1) and the §5 notice text in § Model Tiers; this story adds the script test, the 31 declarations, and the eval note, and repairs the notice text only if Story 1 left it out. Story 2's scaffolder changes (`commands/new-command.md` emits `entry_level` for future commands) cover new commands; this story covers the 31 that exist. Story 4's `require_literal` pins are for escalation sentences in `create-spec.md`/`implement-story.md`, not for `entry_level` — do not add pins for the notice text to `eval.sh` here; the presence note is the only eval surface this story owns. ADR-025 is untouched.

**Verification corrections (recorded during implementation).** (1) AC-5.1's literal `rg -c "^entry_level:" commands/*.md` reports 2 for `commands/new-command.md`, because its Step-3 scaffold literal `entry_level: <high|standard|any>` (line 161, pinned by `scripts/tests/test_model_tier_migration.sh`) sits at column 0 inside a fence. The correct check is frontmatter-scoped — count only lines between the first two `---` fences: `awk 'NR==1&&$0!="---"{exit} /^---[[:space:]]*$/{fm++; if(fm>=2)exit; next} fm==1&&/^entry_level:/{c++} END{print c+0}' "$f"` → 1 for all 31, 0 for `_preamble.md`.
