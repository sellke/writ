## Specification Contract

**Deliverable:** In this repo, Claude Code registers the nine `writ-*` agents: `.claude/agents` points at `claude-code/agents/`, the folder of generated Claude Code agent files. Every Writ spawn also has a stated fallback for when an agent type isn't registered. A check fails if the repo's `.claude/agents` stops exposing agents with frontmatter.

**Must Include:**
- `/implement-story` in this repo can spawn `writ-coder`, so Gate 1 no longer has to be waived.
- When no coding-agent type exists, Gate 1 never codes inline: it uses the fallback spawn or BLOCKED escalation.

**Hardest Constraint:** `commands/implement-story.md` is over its byte budget with an exact pinned overage (`KNOWN_OVER_BUDGET` in `scripts/tests/test_governor_enforcement.py`). Every added sentence needs an offset or a disclosed ledger entry. `2026-10-25-gate-upgrade-removal-measurement` (in progress) depends on presence probes in `implement-story.md`, and those must keep passing.

**🎯 Experience Design:**
- **Entry point:** `/implement-story`, `/implement-spec` or an `/implement-phase` lane, run in this repo from a Claude Code session.
- **Happy path:** Gate 1 spawns `writ-coder` by name, as `adapters/claude-code.md` Agent Paths says. The What Was Built record names the agent that coded.
- **Moment of truth:** the session's agent list includes `writ-coder`, `writ-evaluator`, `writ-reviewer`, `writ-supervisor` and the other five.
- **Feedback model:** `eval.sh --check=claude-agents` passes; the story report names the Gate 1 agent.
- **Error experience:** if a session has no `writ-*` types (for example, it started before the agents were registered), Gate 1 spawns a general-purpose agent told to read and follow `agents/coding-agent.md`, and says so. If no spawn is possible at all, Gate 1 goes to the BLOCKED escalation (retry / skip, marking the story degraded / abort), never inline coding.

**📋 Business Rules:**
1. `.claude/agents` stays a symlink to product source, now `../claude-code/agents`. `.cursor/agents` stays `../agents`. No regular-file copies (CLAUDE.md's symlink rule).
2. `claude-code/agents/` stays generated by `scripts/gen-claude-agents.py`. Edits go to `agents/*.md` and get regenerated. `gen-claude-agents.py --check` and `gen-platform-trees.py --check` stay clean.
3. Fallback order for every spawn on Claude Code: the registered `writ-*` type first; otherwise a general-purpose agent whose prompt starts by reading and following the canonical `agents/<file>.md`. The report records which one ran.
4. Code written by the orchestrator itself, with no coding spawn, is not a Gate 1 pass. The supervisor ESCALATEs when a report shows it.
5. Installs into other projects don't change. `install.sh` already copies `claude-code/agents/`.

**Success Criteria:**
- **Check:** a test plus an eval check pass on the repointed link, and fail on a fixture where `.claude/agents` exposes only files without frontmatter.
- **Live:** a fresh Claude Code session in this repo lists the nine `writ-*` agent types. Recorded as a run, since the authoring session can't re-list agent types.
- **Suites:** pytest on 3.9 and 3.14, the bash tests, `eval.sh`, and both generator `--check`s stay green.

**⚠️ Technical Concerns:**
- **Agent list is read at session start:** Claude Code reads `.claude/agents/` when a session starts, so the authoring session can't prove registration live. The live check has to run in a fresh session (`claude -p` or a new desktop session).
- **Generated files behind a familiar path:** `writ-coder` declares `isolation: worktree` and `memory: project`. Once registered, coder spawns in this repo run in a worktree, and editing `.claude/agents/writ-coder.md` edits a generated file. `gen-claude-agents.py --check` catches hand edits.

**💡 Recommendations:**

## 🎯 Experience Design

### User journey

1. The maintainer starts a Claude Code session in this repo. Claude Code loads `.claude/agents/`, which now resolves to `claude-code/agents/`, and registers `writ-architect`, `writ-coder`, `writ-documenter`, `writ-evaluator`, `writ-reviewer`, `writ-story-gen`, `writ-supervisor`, `writ-tester`, and `writ-visual-qa`.
2. `/implement-story` reaches Gate 1 and spawns `writ-coder` per `adapters/claude-code.md` Agent Paths. Gate 3 spawns `writ-evaluator` or `writ-reviewer`; `/implement-spec` spawns `writ-supervisor`.
3. The What Was Built record names the agent that coded, so the supervisor can verify the claim.

### State catalog

| State | Condition | Behavior |
|---|---|---|
| Registered | session started after the repoint | spawn `writ-*` by name |
| Unregistered | session started before the repoint, or another harness without the types | spawn a general-purpose agent briefed to read and follow `agents/<file>.md`; the report says so |
| No spawn possible | the harness has no subagent tool | Gate 1 BLOCKED escalation; never inline coding |
| Broken link | `.claude/agents` missing, dangling, or pointing at files without frontmatter | `eval.sh --check=claude-agents` finding |
| Install | another project's `.claude/agents/` (copies from `install.sh`) | unchanged; the new check does not run there |

## Business Rules (Expanded)

**Business Rule 1.** The repoint keeps the self-dogfooding model: one symlink per platform folder, each to product source. `claude-code/agents/` is product source (it ships through `install.sh` and the plugin). `.writ/docs/self-dogfooding.md` names the new target.

**Business Rule 2.** Hand edits under `.claude/agents/` now land in generated files. The generated header already says "do not hand-edit", and `gen-claude-agents.py --check` reports drift.

**Business Rule 3.** The fallback is a spawn, not a shortcut. The general-purpose agent gets the same inputs the named agent would and starts by reading its canonical definition. The report names the agent type that ran (for example `writ-coder` or `general-purpose (agents/coding-agent.md)`).

**Business Rule 4.** Inline coding by the orchestrator was the Phase 16 failure mode. It now fails closed twice: Gate 1 routes to the BLOCKED escalation instead, and the supervisor ESCALATEs a report whose code has no coding spawn.

**Business Rule 5.** The eval check runs only in the Writ source repo: it applies when both `claude-code/agents/` and `.claude/agents` exist under the project root. A temp copy or an install without `.claude/agents` gets no finding.

## Detailed Requirements

- **Symlink:** `git rm .claude/agents` then `ln -s ../claude-code/agents .claude/agents`, committed as a symlink (mode 120000).
- **Eval check:** extend `check_claude_agents` in `scripts/eval.sh`. When `$PROJECT_ROOT/claude-code/agents` is a directory and `$PROJECT_ROOT/.claude/agents` exists, list the `name:` values from the frontmatter of every `*.md` under `.claude/agents/`. The set must equal the `name:` set of `claude-code/agents/*.md`. Each missing name, and each file with no frontmatter `name:`, is one `add_finding` naming `.claude/agents`, with remedy `ln -sfn ../claude-code/agents .claude/agents`.
- **Test:** cases in `scripts/tests/test_eval_claude_agents.sh` (temp copy): the repointed link passes; a link to a folder of frontmatter-less copies of `agents/*.md` fails with the finding; a copy with no `.claude/agents` passes.
- **Adapter:** `adapters/claude-code.md` § Agent Paths gains the fallback rule after "Spawn the `writ-*` agent by name."
- **Gate 1:** one sentence in `commands/implement-story.md` Gate 1: no `writ-coder` type → the adapter's fallback spawn; no spawn possible → BLOCKED escalation; never inline coding. Offset in the same file, or a disclosed ledger entry.
- **Supervisor:** `agents/supervisor-agent.md`'s ESCALATE rule lists "code in the commit range with no coding-agent spawn in the report". Regenerate `claude-code/agents/writ-supervisor.md` and run `gen-platform-trees.py`.
- **Live run:** a fresh session lists the nine types. Record the command and output as a `Verified by` line.

## Implementation Approach

Two stories. Story 1 changes the link, the dogfooding doc, and the eval check with its test; it touches no command. Story 2 changes prose in the adapter, `implement-story.md`, and the supervisor definition, then regenerates trees and pins. Python 3.9 floor and bash 3.2 compatibility for the eval check (macOS system bash).
