Each row states the degradation when no renderer is available: a written structural description, said out loud, never a silent skip. Update every Writ-command reference: `.writ/manifest.yaml`, `SKILL.md` (regenerate via `gen-skill.sh`), `README.md`, other commands (e.g. `create-spec.md` Step 1.5 "wireframe conventions from `/design`", `prototype.md`, any others the inventory finds), adapters, `claude-code/CLAUDE.md` (generated by the dependency spec's generator — regenerate it, do not hand-edit), generated Codex files if any, eval pins, and tests. 3. Upgrade path: a project that has the old `design.md` installed gets it removed as a stale file when unmodified and kept with a warning when modified (the mechanism from `2026-10-20-ci-and-update-integrity`); `writ-design.md` is installed. ## Technical Concerns

A modified `commands/design.md` is kept silently on the first update and deleted on the second (`.writ/issues/bugs/2026-10-12-update-deletes-modified-stale-files.md`). Story 3's modified-file criterion fails until that spec lands. This spec does not patch `update.sh`. That spec keeps the warning text as it is today, so the expected line is `⚠️  Stale (no longer shipped, locally modified — kept): commands/design.md`.
- `install.sh` supports three platforms (`cursor`, `claude`, `codex`). OpenClaw has no install path (`adapters/openclaw.md` § Skills → Install Path), so "each platform" in the install criteria means those three. OpenClaw still gets its adapter row.
- The grep in the contract also matches strings that are not command references: `.writ/docs/design-system.md`, "roadmap/design", "artboard/design". The gate uses anchored patterns so these do not count (sub-specs/technical-spec.md → Reference Gate).
- Three dated snapshots outside the listed record paths name `/design`: `.writ/docs/leanness-audit-2026-07-11.md`, `.writ/docs/swot-2026-03-01.md`, and `.writ/explanations/2026-03-20-WritPipelineArchitecture .md`. Rewriting them would falsify the record, so they stay and the gate names them in its record list. This spec's own folder is in that list too, because it describes the rename, and so is `.writ/specs/2026-10-20-claude-code-parity/`, whose technical spec cites the rename as a generator edge case.
- The roadmap's Phase 13 criterion says the collision fix is "verified by a clean-room install". This spec verifies it with temp-project installs that show no `design.md` lands. It does not check, in a live Claude Code session (2.1.233 or later), whether the native `/design` exists or how a project command would shadow it. The evidence for the native command is secondary reporting (`.writ/research/2026-10-19-prototype-visual-drafts-research.md` F5). The rename removes the collision either way.
- No alias is kept. A `design` alias would bring the collision back. On Cursor and Codex, `/design` stops resolving after the upgrade. That is the breaking change.

## Experience Design

### Who uses it

- **A Claude Code user** who types `/design` or `/writ-design`. After this spec, each name reaches one command and they can tell which one runs.
- **A `/prototype` user on any platform** whose run reaches Step 2.5. The agent finds a translated tool in the adapter, or says plainly that the drafts were not rendered.
- **A user upgrading an existing install.** `update.sh` or `/update-writ` replaces `design.md` with `writ-design.md`. Their edits survive with a warning.
- **The maintainer.** The gate test names any reference the rename missed, by path and line.

### Journey

1. Entry: the user runs `/prototype` on an unsettled UI idea, or runs `update.sh` on a project installed before this release, or types `/writ-design`.
2. Happy path (prototype): Step 2.5 asks for the `canvas-preview` capability. The agent reads its adapter row and renders each draft with that platform's tool.
3. Happy path (upgrade): the update prints `🗑  Removed: commands/design.md` and installs `commands/writ-design.md`. The CHANGELOG's breaking-change entry says to run `/writ-design` from now on.
4. Moment of truth: on Claude Code, `/design` no longer opens Writ's wireframe flow, and `/writ-design` opens it with the same modes and flags as before.
5. Feedback: the update summary lists the removed file. The prototype run says which renderer it used, or that it used none.

### State Catalog

| State | What the user or maintainer sees |
|---|---|
| `/prototype` Step 2.5 on Cursor | Drafts render in the `cursor-ide-browser` canvas. |
| `/prototype` Step 2.5 on Claude Code, interactive | Drafts render as artifacts or in the preview pane. |
| `/prototype` Step 2.5 on Claude Code, no artifact or preview tool (e.g. headless `claude -p`) | A written structural description per draft, and a plain statement that the drafts were not rendered. |
| `/prototype` Step 2.5 on Codex or OpenClaw | One self-contained HTML file per draft under `.writ/prototypes/<date>-<slug>/`, beside `exploration.md`. The agent gives the paths. |
| Codex or OpenClaw run that cannot write files (read-only sandbox) | A written structural description per draft, stated as unrendered. |
| Fresh install, any of the three install platforms | `<platform_dir>/commands/writ-design.md` exists. No `design.md`. The manifest records only the new path. |
| Update, old `design.md` unmodified | Dry run lists `🗑  commands/design.md` and changes nothing. A real run prints `🗑  Removed: commands/design.md` and installs `writ-design.md`. |
| Update, old `design.md` locally modified | The file is kept byte for byte. Every update prints a stale warning that names `commands/design.md`. |
| User types `/design` on Claude Code after upgrade | Claude Code's native command runs, if their version has one. Writ's command is not reached by that name. |
| User types `/design` on Cursor or Codex after upgrade | No Writ command answers. The CHANGELOG upgrade note says to use `/writ-design`. |
| Maintainer leaves a Writ `/design` reference in a shipped file | The gate test fails and prints `path:line: text` for each hit. |
| Maintainer adds a line about Claude Code's native `/design` | The gate passes when the line writes it as "native `/design`". |

### Interaction Patterns

- Commands name the capability (`canvas-preview`), and adapters name the tool. A reader of `prototype.md` never needs to know a vendor tool name.
- Degradation is said out loud. A run that could not render tells the user so in the same message as the drafts.
- Gate failures print one line per hit, so each fix is one edit.

## Business Rules (Expanded)

1. **Capability name.** The capability is `canvas-preview`. `commands/prototype.md` uses that name in Step 2 (the Figma MCP detection sentence) and in Step 2.5's "Render through the platform" table. It names no vendor tool.
2. **Adapter row shape.** Each adapter's existing tool-mapping table gets one row whose first cell is `` `canvas-preview` ``. The row names the platform's mapping and ends with the degradation clause: "No renderer: write a structural description of each draft and say the drafts were not rendered." The test checks for the phrases `structural description` and `not rendered` in that row.
3. **Platform mappings.** Cursor → the `cursor-ide-browser` canvas. Claude Code → an artifact, or the preview pane. Codex and OpenClaw → one self-contained HTML file per draft (inline CSS, no network fetch), written to the run's `.writ/prototypes/<date>-<slug>/` folder.
4. **Step 2.5 stays as PR #59 wrote it.** The three-row render table, its "best available first" order, and "Never degrade silently" stay. Only the middle row's label and the adapter pointer sentence change. No new mode, step, or gate.
5. **Rename is name-only.** In `commands/writ-design.md`, only lines where the command names itself change: frontmatter `name:`, the H1, the invocation table, and in-body `/design` self-references. Modes, flags, exit criteria, and outputs are unchanged.
6. **History is kept.** The file moves with `git mv`, so `git log --follow` and `git diff -M` show a rename. The `.claude/` and `.cursor/` symlinks in this repo stay symlinks.
7. **Reference classes.** Each match of `git grep -n -e '/design' -e 'design\.md'` is one of: Writ-command reference (rename); Claude Code native `/design` (keep); historical record (keep); not a command reference, e.g. a `design-system.md` path (keep). The inventory in `sub-specs/technical-spec.md` classifies every match found on 2026-10-20.
8. **Generated files are regenerated.** `SKILL.md` comes from `bash scripts/gen-skill.sh`. `claude-code/CLAUDE.md` comes from `scripts/gen-claude-md.py`, which `2026-10-20-claude-code-parity` adds. Neither is hand-edited. `codex/AGENTS.md.template` is hand-maintained today and gets a hand edit, unless the parity spec has put it under a generator by then. No Codex TOML names the command, so none is regenerated.
9. **No alias.** The manifest entry for `writ-design` has no `aliases: [design]`. No file named `design.md` remains under `commands/`.
10. **Manifest order.** The commands list in `.writ/manifest.yaml` is sorted by name. `writ-design` moves to the end of the list, after `verify-spec`. Its category, purpose, and tags stay.
11. **Upgrade mechanism.** The upgrade relies only on stale detection: the manifest lists `commands/design.md`, and upstream no longer has it. No rename map is added to `update.sh`. Unmodified → removed. Modified → kept with a warning on every run, using the mechanism from `2026-10-20-ci-and-update-integrity`.
12. **Gate record list.** The gate ignores hits under the contract's record paths, this spec's own folder, the parity spec's folder, and the three dated snapshots named under Technical Concerns. Every other hit fails, except a line that names Claude Code's command as "native `/design`".
13. **Test isolation.** Install and update tests run in temp directories from a committed copy of the working tree. Never run `install.sh` or `update.sh` against the Writ repo itself.
14. **Runtime.** Tests are Python 3.9 standard library and POSIX bash, matching the repo floor.

## Implementation Approach

- **Order.** Story 1 first: it is independent and small. Story 2 depends on Story 1 because both edit `commands/prototype.md` and `adapters/cursor.md`. Story 3 depends on Story 2, since its tests read the renamed tree.
- **Cross-spec order.** `2026-10-20-claude-code-parity` must land before Story 1, because it rewrites parts of `adapters/claude-code.md` and owns the `claude-code/CLAUDE.md` generator. Story 3's modified-file criterion also needs `2026-10-20-ci-and-update-integrity`. `2026-10-20-harness-cuts` (a dependency of the parity spec) deletes the `*.lean.md` siblings, and it and the `create-spec` reduction pass may edit `commands/create-spec.md` and `commands/prototype.md`. Find edits by section heading and text, never by line number, and re-run the inventory grep before each edit.
- **One test file per concern.** `test_platform_neutral_names.py` holds the static checks (canvas rows, registration, reference gate). `test_install_update_writ_design.sh` holds the install and update behavior.
- **Gate as a function.** The gate is `writ_design_refs(root)` in the test module. The real-repo test calls it on the repo root. The fixture test calls it on a temp git repo, so the gate's teeth are shown without editing real files.
- **Verification.** `uv run --python 3.9 pytest`, `for t in scripts/tests/test_*.sh; do bash "$t" || echo "FAIL $t"; done`, and `bash scripts/eval.sh` (outside any sandbox, since it runs `git init` in a temp dir) after every story.

## Upgrade Note

*For `/release` to carry into the CHANGELOG under `### Breaking Changes`.*

**`/design` is renamed to `/writ-design`.** Claude Code now ships its own `/design` command. Writ's wireframe and mockup command used the same name, so on Claude Code you could not tell which one would run. Writ's command is now `/writ-design`. It works the same way: same modes, same flags (`--wireframe`, `--screenshot`, `--compare`), same output under the spec's `mockups/` folder.

- Type `/writ-design` wherever you typed `/design`. On Claude Code, `/design` now reaches the platform's own command, if your version has one. On Cursor and Codex, `/design` no longer reaches anything from Writ.
- Running `update.sh` or `/update-writ` installs `commands/writ-design.md` in `.cursor/`, `.claude/`, or `.codex/`.
- If you never edited `commands/design.md`, the update removes it and prints `🗑  Removed: commands/design.md`.
- If you edited it, the update keeps your copy and prints `⚠️  Stale (no longer shipped, locally modified — kept): commands/design.md` on every run. Until you delete it, `/design` in that project still opens your old copy, including on Claude Code. Move your edits into `writ-design.md`, then delete `design.md`.
- Notes, scripts, or custom commands of your own that say `/design` or `commands/design.md` need the new name. Writ does not rewrite files it does not own.

*Before release, Story 3 Task 3.5 checks the removal and warning lines above against the output `update.sh` actually prints.*
