## Method

- **Base:** `f054e9d`, the parent of the spec's first implementation commit `16048cd`. That commit also added the spec package, so both arms take `spec.md`, `spec-lite.md`, `technical-spec.md`, and the stories from `16048cd`, with Story 1's completion bookkeeping (status, checkboxes, What Was Built) reset.
- **arm-original:** the stories as first committed in `16048cd` (the pre-implementation text), with only Story 1's completion bookkeeping reset. The `archive/` copies differ from these only in sections removed or filled in at completion.
- **arm-lean:** both stories regenerated by the Story 2–4 `user-story-generator` at the `floor` tier (haiku), from the same `spec.md` and `technical-spec.md`, given only each story's title, a one-line description, dependencies, and priority. Neither generator saw the original stories.
- **Run:** in each arm, per story in order: Gate 1 `coding-agent` (session model), the orchestrator's own test run, Gate 3 `evaluator-agent` (session model, `reviewer-filters` and `evidence-gate` on), a recode on FAIL, a drift log, and a commit in the arm. The same brief was used for both arms, apart from the worktree path. This is a reduced, hand-run `/implement-story` loop, applied the same way to both arms. Gates 0, 0.5, 2, 2.5, 4, 4.5, and 5 were not run: neither arm has a recipe or coverage tooling, and the full Writ suite at this old commit is not what the stories change.
- **Measured with:** `measure.py` (session scratchpad), plus the gate reports.

### The one substantive difference

`arm-original` Story 1's AC-1.5 and task 1.5 both tell the coder to write the `CLAUDE.md.writ-block` baseline "via `writ_compute_writ_block_inner_hash "CLAUDE.md"`", which hashes the file as it is on disk. After a run that preserves a user-edited block, that records the user's edit as Writ's baseline, and the next plain install overwrites the edit. The coding agent saw this risk, listed it as a concern, and followed the task anyway. The evaluator failed the story (Major) and reproduced the data loss. One recode fixed it.

`arm-lean`'s regenerated Story 1 (criteria and tasks) does not name the hash call. Its task 1.4 says only to "record the Writ block's inner hash under the `CLAUDE.md.writ-block` key ... per Business Rule 1". The coding agent kept the prior baseline on a preserved outcome without being told, and logged that as DEV-001 (Small).

History matches the trial. The August 2026 implementation, built from the original stories, shipped the same bug (`16048cd:scripts/install.sh:704-706` records the current inner hash). It was fixed two months later in `a1c900c` (2026-10-20, "record baselines only for shipped paths").

### What got worse

- `arm-lean` logged one more Small drift entry (4 vs 3). Lean tasks leave more to the coder, so more of its decisions go on record as drift. All were Small, and the evaluator called each one correct for the contract.
- The lean generator over-applied "no internal names": it left the spec's `merge_claude_md` name out of the tasks and put it in Notes. No harm came of it here.

## Limits

- **Sample of one spec, one run per arm.** Model variance alone could account for the data-loss difference. The trial shows no regression; it does not prove an improvement.
- The original arm's prescription and its bug happened together twice (August and today), which is consistent with over-prescription causing the defect. Two observations of one spec are still one spec.
- `[DEV-` counts depend on how strictly each evaluator logs drift; the same evaluator prompt was used in both arms.
- **Confound:** the prescription sat in an acceptance criterion as well as a task, and the lean arm regenerated both. This spec's generator changes cover tasks, the Definition of Done, and context hints, not criterion wording. The difference can be credited to the regenerated story as a whole, and to generator variance, not to the task rules alone.
- Gates 0, 0.5, 2, 2.5, 4, 4.5, and 5 did not run in either arm, so findings and gate rows cover Gates 1 and 3 only.

## Verdict

The regenerated stories cost 28% fewer story words, needed one fewer review iteration, and did not carry the prescription that led the original arm, and the August 2026 implementation, into the one Major defect. That difference cannot be pinned on the task rules alone (see Limits). Nothing measured got worse except one more Small drift entry. Sample size: one spec, two stories, one run per arm.

lean-tasks: keep
