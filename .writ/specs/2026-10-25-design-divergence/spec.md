**🎯 Experience Design:**
- **Entry point:** `/prototype` with an unsettled or UI-touching idea; `/implement-story` on a story whose planned files cross a boundary or classify full-stack, or that runs with `--full-pipeline` or `--panel`.
- **Happy path:** Gate 0 prints the caller usage it wrote, then two sketch commitments, then `gate0-divergence: chose A (<axes>) — <why B lost>`. The coding agent builds from the chosen sketch.
- **Moment of truth:** the two sketches differ in structure (where state lives, how many calls, which table owns identity), not in naming.
- **Feedback model:** one `gate0-divergence:` line in the story report on every Gate 0 run, stating `chose`, `skip`, or `off` with a reason.
- **Error experience:** a failed or incomplete sketch, an empty planned-file set, or an unverifiable route prints `gate0-divergence: skip (<reason>)` and the pipeline continues exactly as it does today.

## Experience Design

### Who uses it

- **A solo builder running `/prototype`** on an unsettled idea. Behavior is unchanged except that the divergence rules now come from the skill.
- **The `/implement-story` orchestrator** on a story whose planned files touch an API, schema, migration, or auth path, or that crosses a recorded overlap. It gets a design sketch before code.
- **The maintainer as blind rater** once, for the trial.

### Journey (Gate 0, boundary-crossing route)

1. Gate 0's arch-check (script on default, agent on `--full-pipeline`) returns PROCEED or CAUTION.
2. Gate 0 reads the switch, then predicts the route from the planned files.
3. On the route, it writes the caller usage to `.writ/state/divergence-<story-stem>.md`.
4. It declares two axes from the skill's catalog for the story's medium and assigns each sketch one combination.
5. It spawns two read-only sketch subagents in one message.
6. It checks each returned sketch for `COMMITMENT:`, `SKETCH:`, and `USAGE FIT:`.
7. It picks the sketch whose usage fit keeps the caller usage simplest, records why the other lost, and appends the chosen sketch to the warnings Gate 1 receives.
8. The story report prints the `gate0-divergence:` line.

### State Catalog

| State | Trigger | Report line |
|---|---|---|
| Off | `- **Gate 0 Divergence:** off` | `gate0-divergence: off (config)` |
| On, malformed | any value other than `on` / `off` | `gate0-divergence: on (malformed: <value>)` |
| Skipped, low stakes | predicted route `evaluator-agent` | `gate0-divergence: skip (route evaluator-agent)` |
| Skipped, unverifiable | empty planned set, crossings `unverifiable`, or a helper that cannot run | `gate0-divergence: skip (unverifiable: <reason>)` |
| Skipped, ABORT | `--full-pipeline` ABORT not resolved as proceed | `gate0-divergence: skip (arch-check abort)` |
| Skipped, sketch failed | a spawn error, or a sketch missing a required field | `gate0-divergence: skip (sketch incomplete: <A|B>)` |
| Chosen | both sketches complete | `gate0-divergence: chose <A|B> (<axis combination>) — <why the other lost>` |

`--quick` and `--review-only` skip Gate 0 and print no line.

### Interaction Patterns

- Every Gate 0 report line starts with `gate0-divergence:`.
- Every trial harness run prints a `divergence-trial:` summary as its last line.

## Business Rules (Expanded)

1. **Switch.** One line under `## Conventions` in `.writ/config.md`: `- **Gate 0 Divergence:** on|off`. Absent means on. Any other value means on and prints the malformed reason, matching the sibling Phase 15 switches (a typo never silently disables a check). Only Gate 0 reads it.
2. **Route.** In order: switch off → off. `--full-pipeline` or `--panel` → on the route. Otherwise run `boundary-map.py compute` (to Gate 0.5's path), `change-surface.py classify --changed <planned>`, and `boundary-map.py crossings --changed <planned> --surface <class>`; `route: review-agent` → on the route, `evaluator-agent` → skip.
3. **Usage first.** The caller usage (3 to 10 lines of calls, requests and responses, or queries a caller would write, taken from the story's acceptance criteria) is written before axes or sketches exist.
4. **Two sketches, independent.** Exactly two, one spawn each, in one message, `readonly`, at the `anchor` tier. Each receives the story, `spec_lite_for_coding`, the caller usage, its own axis combination, and the caller as its persona. Neither receives the other's prompt or output.
5. **Commit before sketching.** Each sketch returns `COMMITMENT:` (its axis combination and the trade-off it accepts) before `SKETCH:` (at most 40 lines of types, signatures, schemas, or a component tree), then `USAGE FIT:` (the caller usage works unchanged, or the exact change it needs).
6. **Choice.** Prefer the sketch whose `USAGE FIT` leaves the caller usage unchanged; then the one with fewer new public names. The reason the other lost is one line.
7. **Hand-off to Gate 1.** The chosen sketch, the caller usage, and the one-line reason are appended to the Gate 0 warnings under the label `design sketch (Gate 0 divergence)`. Gate 1's routing is unchanged; a deviation is ordinary drift.
8. **Never blocking.** No divergence outcome fails Gate 0, marks the story `⚠️ DEGRADED`, asks the user, or increments `review_cycle`. A failed sketch is not retried.
9. **Skill boundary.** The skill owns how to get alternatives that differ. Each caller owns when to run it, what a draft is in its medium, how drafts are shown, and where the decision is recorded.
10. **Trial integrity.** Both arms use the same model, the same brief, and the same output template. Blinding strips `Commitment:` lines, replaces titles with `Draft 1` to `Draft 3`, shuffles drafts within a set, and assigns arms to Set X and Set Y at random per brief. UI drafts are rendered after blinding, from the blinded text.
11. **Trial verdict.** `keep` when the axes arm is the more distinct set on at least 4 of 6 briefs and its total distinct-structure count exceeds the naive arm's. `remove` otherwise; a tie on a brief is not a win. `unverifiable` when any arm, rating field, rater name, or key is missing, or the key or draft text changed after blinding.
12. **Human-gated verdict.** Only a human fills the sheet and runs `rate`. The lane stops at `rating-handoff.md`. An `unverifiable` report is never acted on.
13. **Removal on `remove`.** Delete the skill and its registrations, the Gate 0 block, its Pipeline/Overview/References mentions, and the switch's config-format entry; strip the axes procedure from `/prototype` Step 2.5; re-pin the ratchet downward; record the result in ADR-030 and roadmap Phase 15; set this spec to `Closed — Not Implemented`.

## Implementation Approach

- **Extraction, not rewrite.** The skill body starts from Step 2.5's existing five rules, then adds what the research says the inline version lacks: the anti-pattern with its reason, the medium-agnostic axis catalogs, and usage-first for interfaces. The `/prototype` side shrinks; its frontmatter and pinned structure do not change.
- **Gate 0 reuses scripts that already exist.** The route predictor is `boundary-map.py compute`, `change-surface.py classify`, and `boundary-map.py crossings`, run over Gate 0's existing `--planned` set. No new script, no new `#### Gate` heading (so `verdict-provenance.py` needs no new `gates:` entry), no new agent file.
- **Gate 1 needs no change.** Gate 1 already receives "any arch-check warnings". The chosen sketch travels in that channel.
- **The trial copies the Phase 12 shape.** Schema-tagged JSON, one subcommand per step, an outcome test independent of the harness, the record committed before any removal, and a caveat line in the report.
- **Removal is cheap by construction.** The Gate 0 block is one bold-led paragraph group inside `#### Gate 0` plus one Pipeline cell, one Overview clause, one References entry, and one config-format entry. The removal-measurement spec can turn it off with the config line, and Story 6 or that spec can delete it by those five edits.
