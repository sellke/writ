# Phase 14 Acceptance Coverage Audit

Base commit `9e7eab5`, compared with `HEAD` `1f83680` on `phase/14-front-door-and-distribution` (60 commits). The shipped change surface is 33 entries: 31 single files plus two generated units, `plugins/writ/` (105 files) and `cursor/plugin/` (61 files). `scripts/gen-platform-trees.py` generates every plugin manifest (`.claude-plugin/marketplace.json`, both `plugin.json` files, `output-styles/writ.md`); neither plugin has hooks or settings files, so no manifest is listed apart from its unit except the root marketplace file.

The five UAT plans hold 73 scenarios. 19 are behavior class: they run Claude Code, Codex, or Cursor. 15 of those passed, all on Claude Code. Four are open: plugin-distribution S3 (GitHub install, blocked until merge), plugin-distribution S5 (Cursor plugin), rendering-delegation-rows S7 (Cursor), and rendering-delegation-rows S8 (Codex; the CLI half ran and passed on 2026-10-24, the Desktop half did not). No Cursor session ran for any Phase 14 scenario. The only Codex run is the `/prototype` CLI half.

Two context limits apply to the passing Claude Code runs:

- Front-door S1 to S11 and generated-platform-trees S6 ran in a clone of the Writ repository, where `.claude/` links to the source and `adapters/` is present. They show what `commands/writ.md` and `commands/create-spec.md` do. They do not show what an install.sh project's CLAUDE.md block or Capability Map does.
- Installed-project runs exist only for the Claude Code plugin (plugin-distribution S2, S9), for `/prototype` in an install.sh Claude Code project (rendering-delegation-rows S3), and for `/prototype` in an install.sh Codex project (rendering-delegation-rows S8, CLI half).

Result: 83 claims. 60 are gaps: 8 high, 18 medium, 34 low impact. 23 claims have a behavior check that ran with a recorded passing result (C43 rests on the CLI half of the still-open rendering-delegation-rows S8). A claim is a gap when no behavior-class scenario has run and passed for it; an open behavior scenario is listed but does not close the gap. Classes: behavior runs the product on a real platform; structural runs a repo script or test (installers and `claude plugin validate` included); text reads or greps files. OpenClaw claims use platform `all` in the JSON because the schema has no OpenClaw value.
